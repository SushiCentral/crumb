# Unified Vim Jump History Implementation Plan

**Status:** implemented in the owned files below; focused node tests and the
type gate pass in this lane. Browser/Playwright, full-suite, and build runs
belong to the parent.

**Goal:** Make `Ctrl-o` / `Ctrl-i` one chronological jump history across native
within-file jumps and Crumb file/tab transitions, with native motions, counts,
marks, searches, and `''`/`` ` `` keeping their pinned-engine behavior.

**Scope (owned files):**
- `src/lib/vim/jump-history.ts` (new): pure bounded history.
- `src/lib/vim/lifecycle.ts`: jump-list method replacement + handler dispatch.
- `src/lib/vim/session.ts`: session-owned history, transition recording,
  pending navigation/token handling.
- `src/lib/vim/shortcuts.ts`: add `i` beside `o` to the built-in Ctrl set.
- `src/App.tsx`: register a current-ref navigator that activates the target tab.
- Focused node tests: `tests/vim-jump-history.test.ts` (new),
  `tests/vim-jump-lifecycle.test.ts` (new), plus additions to
  `tests/vim-session.test.ts` and `tests/vim-shortcuts.test.ts`.
- `tests/e2e/app-vim-jumps.spec.ts` (new, authored but not executed here).
- This plan.

**Explicitly not touched:** `src/lib/vim/extension.ts`, `src/lib/vim/surround.ts`,
`docs/vim.md`, comment/surround specs.

## 1. Verified engine facts

`node_modules/@replit/codemirror-vim-core/vim.js`:

- `resetVimGlobalState()` creates `jumpList: createCircularJumpList()` (lines
  750–770). A global reset replaces the whole object, so method installation
  must be idempotent per object identity.
- `createCircularJumpList()` (line 557) exposes `cachedCursor`, `add(cm, oldCur,
  newCur)`, `move(cm, signedOffset)`, `find(cm, signedOffset)`. The stock
  implementation stores `cm.setBookmark()` objects.
- Native jumps call `recordJumpPosition()` → `jumpList.add(cm, oldCur, newCur)`
  (lines 2049–2058, 4138–4141). Motions with `toJumplist` include `H/M/L`,
  `{`/`}`, `gg`/`G`, `%`, marks, `n`/`N`, `/`, `?`, `*`, `#`, `g*`, `g#`,
  brackets, and searches (keymap lines 111–259). `j`/`k` do not add entries.
- `<C-i>` / `<C-o>` are `jumpListWalk` actions (lines 202–203) and return early
  in Visual mode (line 2953). `move()`'s marker is immediately `find()`-ed and
  the cursor is set from it (lines 2958–2963).
- `find(cm, -1)` is also used by `getMarkPos()` for register `'`/`` ` ``
  (line 5579). The engine converts an undefined result to `Pos(0, 0)`.

## 2. Jump-list bridge (lifecycle)

- Patch the actual object methods, never replace the object, so engine-owned
  `cachedCursor` survives. Track patched objects in a `WeakSet`.
- Keep a `WeakMap<CodeMirror, EditorView>` populated by `patchVimAdapter` and by
  handler registration/`getCM(view)`.
- `registerVimJumpHandlers(view, handlers)` is called from `attachPane`; its
  generation-safe unsubscribe checks the exact handler instance.
- Dispatch to the registered view handler when present. For unregistered
  fixtures, use a small adapter-local plain-position fallback; never call the
  old bookmark-backed closures.
- `add` returns void and increments a per-adapter jump version.
- `move` invokes the session handler synchronously (which reserves and queues a
  microtask) and returns `undefined`, so the native action re-sets the source
  cursor to itself and does not double-jump.
- `find` returns only same-document positions from the session, otherwise
  `null`, so `''`/`` ` `` never receives foreign coordinates. Fallback find is
  adapter-local.
- Preserve `cachedCursor`; when the last registered view unregisters, delete it
  from the current global list (teardown).
- Re-ensure the bridge from the existing `Vim.handleKey` capture wrapper so a
  global-state reset is repaired before the next command.

## 3. Native landing correction

The engine records `newCur` *before* `installStartoflineCapture` applies the
`nostartofline` goal column (lifecycle lines 410–471). In the existing
`executedTarget && !insertMode` branch only:

- compare the adapter's jump version before/after `handleKey`;
- when the command actually added a jump, ask the registered handler to correct
  the last destination (`ch` only, same line);
- never correct for `j`/`k` or any command that did not add a jump, and do not
  add a timer or coalesce every key.

## 4. Pure history (`jump-history.ts`)

- `VimJumpLocation { documentId, line, ch }`, zero-based, plain data only.
- Bound: 100 entries.
- `record(from, to)`: ignore no-ops; truncate forward entries; if the live
  departure differs from the recorded current entry, append the departure first
  (this keeps an unrecorded move addressable); dedupe adjacent exact entries
  only.
- `walk(current, signedOffset)`: reserve/move the pointer and return the target.
  A differing unrecorded `current` is inserted as the newest entry (replacing
  the forward branch) so the opposite direction returns there. That insertion
  runs through the same 100-entry trim as `record`, and the effective pointer is
  recomputed from the surviving tail. Counts traverse the same single list.
- Invalid native positions are never stored: `record` rejects
  non-finite/negative coordinates (fractional values are truncated) and
  `clampJumpLocation` sanitizes NaN/Infinity document/line/column inputs.
- `findSame(current, offset)`: pure (no pointer mutation), scans only entries in
  the current document; used for `''`/`` ` ``.
- `correctDestination(to)`: replace the last destination's same-line `ch`
  after lifecycle goal-column correction.
- `prune(isOpen)` adjusts the pointer around removed documents.
- `snapshot()` / `restore()` are used to roll back a rejected navigation.
- Positions are clamped by the session on restore; edits are not tracked.

## 5. Session integration

- Session owns one history instance, `setJumpNavigator()`, and one pending jump
  token. No second native/file stack.
- Native `add` is recorded only for the enabled, ready, current owner and only
  while not replaying; location document ids come from the binding.
- Real document transitions only:
  - `finalizeOwner` captures the live departure while the adapter is still
    alive (`view.state.selection.main.head`);
  - `syncOwner` records departure → restored destination only when the document
    ids differ;
  - same-document owner changes, Vim toggle, StrictMode replay, external focus,
    detach/closure, and the closed fallback clear or skip the departure.
- `walk` requests:
  - reserve the history pointer synchronously;
  - when a request is already pending, chain the next offset from the reserved
    target so rapid `Ctrl-o Ctrl-o` advances two entries;
  - queue exactly one `queueMicrotask` host activation; newer tokens win;
  - on navigator `null`/unrelated transition/disable/closure/detach/external
    intent, restore the pre-chain history snapshot so a rejected navigation
    cannot advance the pointer.
- Host navigator contract `(target) => { paneId } | null`:
  - App uses current `tabsRef`/`panesRef`, prefers the invoking editor pane,
    calls `activatePaneTab`, and returns the pane id or `null` if the document is
    no longer open;
  - it does not focus; the session applies selection/scroll/focus after Vim
    state is restored.
- `afterTransition`/`syncOwner` apply the pending selection only when the
  binding matches the pending pane + document id; clamp line/ch to the actual
  document. Pending is consumed before focus so focus reentry cannot cancel it.
- `reconcileDocuments` prunes history for genuinely closed documents while
  keeping currently attached/pending ids (handles reconcile readiness lag).

## 9. Implementation notes / deviations

- `VimSessionAdapter` gained an optional `registerJumps` seam. Production uses
  `registerVimJumpHandlers`; session unit tests inject a fake bridge so they do
  not import the Vim package or a browser adapter.
- Column correction is gated by a per-adapter native-add version counter rather
  than by motion name alone. This is what keeps corrected `gg`/`G`/`H`/`M`/`L`
  landings from ever rewriting history for `j`/`k` or edits.
- The App navigator always prefers the focused editor pane, so an ordinary
  `Ctrl-o`/`Ctrl-i` stays in the invoking pane instead of hopping to a split
  that happens to contain the target document.
- The `reconcileDocuments` pruning predicate keeps currently attached
  documents as candidates, so a newly attached document is not treated as
  closed before App's committed-tab set catches up. If the pending target is
  closed, it is cancelled before pruning; remaining rollback snapshots are
  pruned through `pruneJumpHistorySnapshot` so a later reject cannot resurrect
  a closed document.
- A clamped replay landing updates the history entry that the walk selected
  (`updateCurrent`), not only the tail destination. Otherwise a shrunk document
  would turn the clamped cursor into an unrecorded departure and truncate the
  forward branch.
- A genuine native add from the current ready owner supersedes a pending replay:
  it rolls the reservation back, clears replay suppression, and records the new
  jump. Non-owner/stale adapters remain ignored.
- Replayed landings go through the adapter's optional `restoreCursor` seam.
  Production uses `restoreVimJumpCursor`, which dispatches selection/scroll and
  refreshes the lifecycle `vimGoalColumns` cache before focus, so the next
  `G`/`gg`/`j`/`k` uses the restored column rather than the pre-jump goal.

## 10. Limits

- Plain positions do not track edits; they clamp against the live document when
  restored.
- `''`/`` ` `` only returns a same-document history position; a cross-file
  previous jump falls through to the engine's `Pos(0,0)` fallback, because the
  pinned engine has no cross-file mark API.
- A rejected cross-file navigation waits for an `afterTransition` or an
  explicit cancellation event; there is deliberately no timeout.
- If a host transition never reports readiness, the pending reservation remains
  until an unrelated transition/disable/closure cancels it.
